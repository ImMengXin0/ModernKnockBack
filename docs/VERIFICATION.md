## 1.2.10 历史对照与本轮缺陷复现

2.0 发布时曾把 1.2.10 与 2.0 Jar 的40个 `combat/rod/compat` 类逐项比较 SHA256，全部一致，结果保存在 Git 标签 `v2.0` 的本文件。当前未找到原1.2.10 Jar，使用该已校验标签核查历史逻辑：零伤害 `THROWN` 命中、一次独立 KB、即时速度后补受击效果、固定0.3碰撞余量和默认10 tick共同保护都已存在。当前保留这些关键规则，鱼钩表现沿用2.0.5-r1的微小回弹。

修复前新增5项分支回归，其中4项复现失败：取消 `KnockbackProfileEvent`、取消 `KnockbackModifyEvent`、API 选到不存在的 profile、选中禁用 profile。这些分支按接口约定保留原生 KB，核心已改变速度，插件却因没有完成自定义修改而判失败，撤回保护且未发送即时速度/受击反馈。真正取消原生 KB 的对照项通过，表明两类取消必须分别处理。

2.0.5-r2 按最终原生事件是否接受完成鱼竿命中，不要求本次必须改写自定义向量。新增回归全部通过：4种保留原生向量的分支、原生取消对照、同次处理嵌套 KB、双射手交替连杆与第10 tick边界、速度事件及动画回调换区。逐项检查单次速度/红闪/声音、零扣血、保护期不被新杆续期或清除，Folia 清理不读写外区实体。

三核心探针实际调用 `RodVelocity.forServer`、Craft受击动画广播和后续 `ServerEntity.sendChanges()`：本人及旁观者先收到速度再收到受击动画，取消速度时两种包都不发；后续 tracker 不给本人发送第二次速度。正常观察者同步保留。发包回调产生的新 `hurtMarked` 不被旧发送清除。该探针模拟世界与连接，单测模拟核心最终应用向量；均不等于完整真人命中与渲染测试。

反馈继续在速度之后、同 tick 内处理；未恢复2.0.6的前置反馈或鱼钩附着/隐藏。客户端可能同帧显示红闪和位移，以上事件与包检查不能保证真人画面的先后帧数。

## Classic 技巧与速度同步

- jump reset 必须具有跳跃输入、真实跳跃事件及同 tick 对应的成功移动。覆盖输入先到/后到、松键、普通击飞、晚取消、重定向、落地、窗口边界、tick溢出、模式/配置身份、排除玩家、Bot、飞行/游泳/载具、传送/重生/退出和Folia外区不读实体。
- 同 tick STOP→攻击→START 保留当前命中快照，下一次攻击使用新状态；较早的定时清理不能删除较新的快照。双方实体年龄不同、攻击者随后推进tick、交换双方时，已接受伤害的上下文仍由受击者时钟及事件身份控制。
- 左右镜像、旋转与连续转向中，默认零保留率不积累侧向偏差；有效jump reset按原半动量规则保留方向，未增加基础推力或ping倍率。
- 速度保护覆盖实际最终速度、后续KB事件修改、同步插件直接改实体、原KB/伤害晚取消、事件取消、排除/模式变化、嵌套新命中、过期近战和鱼竿现有短窗口。
- 三核心真实执行 `Player.causeExtraKnockback` 的速度派发分支、`CraftEntity.getVelocity/setVelocity` 与 `ClientboundSetEntityMotionPacket` 构造。事件初值等于目标速度时，模拟同步插件直接改实体Y，旧的“只改事件”保护实际发出错误Y；修复后发出预期向量且只有一个速度包，无递归事件，核心清除hurtMarked并按原生规则恢复发送前运动。
- Leaf 分别检查 `flushKnockback=false/true`。开启时执行真实 `ServerEntity.sendChanges`，确认两次同步速度事件和实际栈分类；只保护第一事件的对照组复现错误Y，修复组保留预期最终速度且只向本人发送一个速度包。单测另外覆盖第二事件重新捕获运动、非原生路径不借用资格、事件取消、新命中及定时清理。

该native探针模拟玩家构造、外部插件事件派发、世界与连接，仅执行实际发包分支，不覆盖完整近战伤害/客户端物理。不同到达顺序的单测不是RTT压测；尚未执行真实低延迟/高延迟客户端对打。玩法说明与复测表见 [Classic 技巧与延迟](CLASSIC-TECHNIQUES.md)。

## 鱼钩回弹与清理

- 成功命中使用接触前的方向计算玩家 KB；鱼钩轻微回弹，随后发送玩家速度，再播放固定方向受击效果。没有附着或隐藏调用。免疫/取消接触仍消耗鱼钩的一次接触，不强制补 KB。
- 回弹恢复为 `(-vx * 0.1, -max(0.05, abs(vy) * 0.1), -vz * 0.1)`；重复清理不反转或加速钩子，非法向量安全回退，Folia 外区不读取或修改钩子。该速度仅作用于鱼钩。
- 鱼钩自身持久数据记录已接触状态：同一枚钩在受击者免疫结束后仍不能再次造成KB，重建监听器也不会重置它。新鱼钩继续遵守共同的10 tick窗口。
- 首次碰撞不再记作收杆，实际收杆后才开始recast-delay；保留钩继续受距离/寿命限制，取消的接触不进入后续补判。
- 原生探针执行 `FishingHook.preHitTargetOrDeflectSelf`，检查重复取消的接触不进入原生命中逻辑，不附着、不移除钩子、不拉回目标。
- 单测继续覆盖收杆、reset、持竿者退出、正常停服及外区不读写，以及速度发送后模式/区域变化时跳过过期反馈。原生完整钓鱼 tick 未运行，不把方法探针当作完整生命周期模拟。

## 普通攻击距离与横扫效果

- 三核心 `ENTITY_INTERACTION_RANGE` 默认值均为3.0。使用真实物品空手/钻石剑/下界合金斧，调用实际 `entityAttackRange` 和 `isWithinAttackRange`：零网络容差下2.99格通过、3.01格拒绝，距离按眼睛到目标包围盒最近点计算。只模拟玩家构造与状态，不覆盖核心范围算法。按用户确认保留原生距离，不作2.99修正。

- 切换到modern/排除接收玩家时恢复横扫声和粒子；移除处理器后正常通过，其他现有通道生命周期检查继续通过。

## Classic 暴击方向回归

先在2.0实现上运行两项事件路径回归，均复现失败，再应用修复并通过完整测试：

- X/Z偏移为 ±0.001 或0、高度差为0/0.25/1.1格时，旧实现会放大小位置误差；例如预期 +X 0.4，实际 X=-0.282842712。修复后方向不随高度差、位置噪声或命中后转头/移动变化。
- 玩家/Bot、地面/空中、疾跑附加、先前速度及重复原生KB组件均覆盖；最终速度保护与首次命中一致，额外组件被拦截。
- 纯向量回归覆盖普通/暴击标记、附魔和高度差；水平距离0.004格及2格仍沿双方相对位置推开，低速鱼竿/箭继续使用飞行方向。

本地1.21.11 Leaf字节码确认 LivingEntity.knockback 在水平距离平方约小于 `1e-5` 时会生成随机方向。旧代码在极小XZ上归一化，且完全重合时用三维长度判断后回退原生向量。2.0.1 在接受伤害时固定近战方向，水平距离平方小于 `1e-5` 时使用水平朝向；不增加配置字段，不用俯仰角或高度差作此判断。

这是已复现的近乎重合场景修复，不代表所有第三方插件或网络条件下的偏转均已复现。jump reset 和显式动量保留的横向速度贡献仍按配置生效。
