# Classic CPS 密度

2.2.0 增加按服务器 tick 采样的密度减退，模拟短促密集点击在对打中的收益。它是有上限的 classic 技巧规则，不等于完整复刻 1.8 客户端或核心物理。

## 采样与力度

仅采样玩家对合格生物实体的原生攻击尝试，不采样挥空或右键。MKB 为防止叠刀而在受击窗口内拦截的攻击仍参与采样；原本可放行但被其他插件取消的攻击不计入。Bot、排除玩家、创造/旁观、飞行、滑翔、游泳及载具状态不获得此收益。

受击时，读取该玩家当前 tick 和前一 tick 的点击数，使用其中较大的一个。两组不相加，因此每 tick 均匀点击一次不会累积为高密度；一次密集点击最多保留到紧邻的下一个 tick。20 TPS 时每 tick 约 50ms，服务器卡顿或网络集中交付会影响观测到的密度，插件不把它当作真实鼠标 CPS 或自动点击检测。

| 单 tick 内攻击次数 | 本插件额外减少的水平退速 |
| --- | --- |
| 0～1 | 0% |
| 2 | 5% |
| 3 | 10% |
| 4 | 15% |
| 5 及以上 | 20%（封顶） |

减退只作用于玩家自身新近战受击向量沿本次击退方向的分量，侧向走位和 Y 不变。先计算基础推力、疾跑/附魔附加及装备抗性，再处理 jump reset 和密度。密度最多减少当时退速的 20%，且不能把结果进一步压低到本次实际水平推力的 25% 以下；jump reset 已到此下限时不再额外减退。显式为 0 的推力和完全抗性不会凭空获得推力；自定义普通 retention 本已产生的反向运动也不会被密度规则反转。

例如无抗性、未疾跑的一击水平推力为 0.4：正常受击为 0.4，密度达到上限时为 0.32；jump reset 后若原为 0.25，则密度上限时为 0.20；若 jump reset 已压到下限 0.10，则仍为 0.10。此处均是速度，不是击退格数。

## 时序与受击保护

受击时只使用此前已收到的攻击尝试。攻击包在本次 KB 计算之后才到达，不会追溯改写或重发这次 KB。不会为了收齐同 tick 点击而延迟命中，不在每次点击后调用 setVelocity，也不会按每次点击把速度继续乘 0.6。

受击间隔、伤害次数、同一击多组件去重、鱼竿接刀保护和原生命中距离仍由原规则控制。多目标的点击共同受该玩家的单 tick 上限约束；右键出杆以及鱼钩/箭的入射 KB 不使用密度减退。密度样本不会通过重载、模式切换、传送、死亡/重生、退出或重启持久保留。

Leaf/Paper 核心及客户端已有的攻击减速继续存在。本项的 20% 上限限定 MKB 新增的密度收益，不能约束其他插件随后直接改速度；25% 下限指 MKB 计算当时的向量，不能保证最终客户端位移有固定格数。

## 配置与验证

`classic/combat.yml` 新增一项，启动或重载 classic 时自动补齐；已有受击间隔及其他配置保留。

```yaml
click-density-enabled: true
```

设为 false 并执行 `/mkb reload` 可关闭密度收益。`/mkb status` 显示 `click density=true (max 20%)` 表示此项开启；modern 不使用此规则。

联机对照时固定装备、药水、地面状态及攻击方向，分别测试均匀点击和密集拖点，然后开启 jump reset 对照。检查受击间隔是否一致、密度收益是否封顶，以及侧移和抬升是否正常。单元测试不能代替真人网络与手感测试。
