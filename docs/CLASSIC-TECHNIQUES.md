# Classic 技巧与延迟（2.0.5）

2.0.4 修复跳跃识别和速度同步时序，2.0.5 补齐 Leaf 立即同步的第二次速度事件保护，并调整受击视角和鱼钩附着，见 [视角、鱼钩与同步](CLASSIC-FEEL.md)。保留已有 KB 数值、`stop_sprint: false`、默认 10 tick 受击间隔和原生普通近战 3 格距离；没有新增调参项，也不需要重置配置。

## W-tap / S-tap

疾跑附加由命中前收到的 START/STOP 疾跑动作决定。一次命中保存自己的状态；同 tick 内之后收到的新动作不改写已经接受的命中，下次攻击使用新的状态。持续按住疾跑仍按既有 `stop_sprint: false` 规则保留附加。

因此 W-tap/S-tap 的作用包括改变移动速度、距离和实际疾跑状态，并不是每次重按都额外叠一层 KB。不会按 W/S 按键猜测攻击，也不会延后一 tick 强制清掉玩家刚恢复的疾跑。

## Strafe

每次有效命中按当时双方水平方向计算，普通位置不掺入攻击者转头朝向。左右镜像或整体旋转的战斗应获得对称推力。默认 `horizontal-retention: 0` 不积累上一击的侧向速度；显式配置非零保留率或有效 jump reset 时，保留动量带来的方向变化属于既定计算。

2.0.1 的极近重合朝向回退继续生效。没有扩大命中范围、挥空补刀或移动回溯。

## Jump reset

此前仅以“地面转空中且速度向上”识别，可能把普通受击抬升认成主动起跳。现在需三项证据：

1. 已收到跳跃输入，或同 tick 内补到跳跃输入。
2. Paper 触发一次向上的跳跃事件。
3. 对应移动成功，起终点没有被改写，事件没有被取消。

确认后松键不抹掉起跳；隔 tick 才按跳不能追认旧击飞。取消/重定向、落地、传送、死亡、重生、退出、重载与模式切换会清理或使证据失效。飞行、滑翔、游泳、载具、排除玩家和 Bot 不使用此判定。

仍采用现有半动量规则：窗口内、受击时仍向上运动，保留命中前 X/Y/Z 至少一半，再叠加相同配置的推力。对着来袭方向移动可以抵消部分水平推力，顺着击退方向移动则可能增加最终速度；jump reset 不是固定“减 KB 倍率”。`jump-reset-window-ticks: 2` 按受击者的服务器 tick 计时，包含第 2 tick 边界；不会按 ping 拉长。

客户端或协议转换未提供跳跃输入时，使用普通空中向量。此规则是高版本上的技巧模拟，不保证等同完整 1.8 客户端物理。

## 不同延迟与 KnockbackSync

已修复以下可以导致相同配置表现不一致的路径：

- KBS 可以直接修改实体速度，而原生发包流程在事件速度未变化时可能跳过写回。现在同时保护事件和实体的实际速度，避免错误 Y 被发送。
- 旧保护可能恢复较早的向量，或在原 KB 被晚取消后继续有效。现在保护发包事件开始时的实际运动状态，并重新核对伤害、KB取消状态及本次记录；新命中不能被旧事件覆盖。
- Leaf 开启立即同步选项时，同一次原生近战会同步产生第二次速度事件。2.0.5 只对该调用路径保留一次后续保护，每次重新捕获当前速度；普通 tracker tick、插件主动刷新及新命中不能复用它。

不延长近战保护 token 的寿命，不按高 ping 增加水平推力，不将被拒绝的攻击排队。KBS 的测量和追踪功能保持原状；classic 的已确认向量仍由 MKB 保护，modern 继续使用自己的共存策略。

服务端到达顺序测试覆盖同 tick 输入切换、双方不同实体时钟、交换攻守和旧记录清理。它不模拟真实网络 RTT、丢包、客户端画面或反作弊。双方真实网络延迟仍会影响看到对手和收到击退的时间。

## 实服复测

保留现有配置，仅替换 Jar 并重启。固定装备、平地和服务器 TPS，先测试相近延迟，再交换高低延迟双方的攻守。可按实际网络选择低延迟/约 80～120 ms/约 150～200 ms 组合，记录真实 RTT 和抖动，不修改玩家 ping 字段冒充网络测试。

| 操作 | 观察点 |
| --- | --- |
| 持续疾跑、W-tap、S-tap，各连续命中 20 次 | STOP/START 后下一次命中是否采用预期附加；受击窗口是否仍一致 |
| 左右绕圈 strafe、双方交换站位 | 对称场景力度是否一致，是否出现无来源的侧漂 |
| 原地受击不按跳，与主动起跳受击对照 | 普通击飞不触发半动量；窗口内有效跳跃才触发 |
| 正面迎击、侧移跳跃、顺击退方向跳跃 | 动量方向影响应可解释，不能把所有跳跃视为固定减击退 |
| 连续鱼竿、竿接刀、近战互打 | 成功鱼钩附着且不挡被钩者视线、收杆无拉回、同一钩不重复受击、10 tick 保护不被绕过 |
| 同场切换 modern，再回 classic | 两种模式恢复各自规则，无旧向量重放 |

若仍有异常，记录双方 RTT、TPS、操作顺序、是否真正按跳、KBS/反作弊版本和使用的 profile。调整基础数值前先区分输入到达、KB向量及客户端显示延迟。

## 源码依据

Paper 1.21.11 的 `ServerGamePacketListenerImpl` 源码中，跳跃事件由地面状态与上升位移触发，不能单独证明玩家按了跳；输入事件在更新服务端输入快照之前派发。因此监听输入时读取事件本身，并以成功移动确认跳跃。

- Paper 原始补丁：`https://raw.githubusercontent.com/PaperMC/Paper/ver/1.21.11/paper-server/patches/sources/net/minecraft/server/network/ServerGamePacketListenerImpl.java.patch`
- Player 输入 API：`https://jd.papermc.io/paper/1.21.11/org/bukkit/entity/Player.html#getCurrentInput()`

发包时序另通过本地 Leaf、ASPaper、Folia 1.21.11 的实际方法验证；详见 [验证记录](VERIFICATION.md)。
