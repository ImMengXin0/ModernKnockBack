# 首次命中初始化开销：修复候选与验证

本文来自 DevXingMC 的 [PR #1](https://github.com/ImMengXin0/ModernKnockBack/pull/1)，整合来源提交为 `6e8e4e7bde77285e6b94916ac96cedbb8afd6ccb`。下文的 Paper/客户端测量为 PR 作者报告，保留其原始口径。2026-11-04 本地 2.3.1 整合保留了额外的 Leaf 栈识别预热、受击包反射预热和网络刷新补丁；维护者此次复核为 331 项自动测试、Leaf/ASPaper/Folia 实际运行库编译与离线探针，没有重新运行下文的联网性能对照。详见 [当前验证记录](VERIFICATION.md)。

## 范围

基于 `fa15355fa22a6082f90c0ea84c120d61d857e81d`（2.3.0）。此变更针对**插件自身在第一次真实命中时才执行的类加载/初始化**，不宣称消除 Java、Paper、其他插件或客户端的全部冷启动成本。

`onEnable` 在读取并验证配置后调用 `CombatWarmup.prepare`：

- 明确列出的战斗热路径类及其嵌套类提前加载、初始化。
- `LeafVelocityDispatch` 的一次性兼容探测提前发生，不等第一刀的速度事件。
- 用不可变 profile 和局部数据做少量纯计算，预热计算分支及点击密度的调用点。
- 不接触真实玩家/实体，不注册或触发假伤害事件，不发包，不调度假命中，不修改配置。
- 不改伤害、受击窗口、击退公式、默认参数或公共事件处理顺序；不增加外部依赖。

纯计算次数固定且很少；这不是“调用几万次强行触发 JIT”的循环。代价是将这部分工作移到启动阶段，而非让它彻底消失。少数依赖真实命中的捕获 lambda 和服务端调用点仍可能在第一刀链接。

第二轮修改将近战路径的清理/提交回调改为显式类，随热路径一并加载，减少首次命中时的捕获 lambda 链接；非旧版斧头不再读取 ItemMeta 来计算本来就为零的伤害修正。条件删除、Leaf generation 清理、调度延迟和伤害规则不变。下方初版记录保留，第二轮结果单独列出。

### 进服与重启的区别

补测上游原版、同一个 JVM 内的三组攻击：第一次登录首刀 22.7591 ms；同账号重进首刀 1.1914 ms；换账号登录首刀 1.2990 ms。没有复现每次登录都重复的高首刀成本。此 PR 针对服务器重启后的首用开销。

### 客户端测量口径

新增 `network` 探针由客户端发送攻击包，另一个客户端记录伤害、受伤动画和击退包。不要把服务端 `PlayerVelocityEvent` 内容当作最终网络包；也不要把 Paper 的 tick-duration 事件当作包含全部包处理时间。

首次网络诊断发现测试客户端依赖对 1.21.11 `LpVec3` 的末尾 int 使用了错误字节序。测试工具现在按实际核心的 `LpVec3.read/write` 格式从原始速度包解码，并检查默认 Classic 向量，未修改正式插件、核心或共享 node_modules。早期 `network-baseline1` 的接收时间仍可参考，但解码出的向量无效，不用作数值正确性结论。

修正探针后，上游 6 刀、第二版 18 刀均通过伤害/受伤动画/速度包断言。实际速度解码为 `(0.3999877922, 0.3607397912, 0)`，与预期一致（量化误差内）。客户端发送第一刀至受击客户端收到非零击退包：上游 27.3910 ms，第二版 13.7530 ms；第二版同账号重进和新账号登录的首刀分别为 1.5192、1.3914 ms。这是本机一次网络对照，不能替代公网、真实客户端或其他核心测试。

第二版自动回归：`mvn test`，322 tests，0 failures，0 errors。新增覆盖非斧头不读取 ItemMeta、条件清理幂等、旧回调不删除新命中，以及 retired 回调的 generation 清理。

第二版另做 modern 模式的 6 次真实客户端攻击冒烟测试：均造成 6 HP，伤害、受伤动画和非零击退包均收到。测试期间未加载 MBedwars 或其他正式服插件。
