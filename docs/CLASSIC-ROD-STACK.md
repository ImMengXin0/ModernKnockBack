# Classic 鱼竿命中与受击保护（2.0.5-r3）

2.0.5-r3补齐零伤害鱼钩的原生伤害通知：同tick先发速度，再发伤害来源通知与固定方向受击动画。通知携带射手和鱼钩，客户端处理受击状态及声音，不再额外播一遍服务端声音，也不额外调用damage或修改血量。保护检查独立于profile/API向量修改，无正伤害记录的原生击退和选择保留原生向量的分支也必须遵守共同窗口。已有9/9/9配置仍按9 tick执行；T到T+8拒绝，T+9可再次命中。这限制窗口内堆叠，不禁止保护结束后继续击退。

`/mkb status`新增`Classic rod`的contacts/accepted/rejected/feedback计数。feedback仅代表已提交反馈包；真人红闪与声音仍待目标服验收。左键持竿走普通近战，不伪造成右键鱼钩的零伤害攻击。自动检查与已复现的时序问题见[验证记录](VERIFICATION.md)。

只修改 ModernKnockBack，不改核心、ThePit 或旧 KnockbackManager。classic 的近战仍使用原生攻击目标/距离，不恢复挥空补刀。

## 查证结果

联网读取了公开的 Spigot 1.8 源码镜像，并与本地 CraftBukkit 1.8.8 字节码交叉检查：

- [EntityFishingHook.java](https://github.com/Attano/Spigot-1.8/blob/master/net/minecraft/server/v1_8_R3/EntityFishingHook.java)：每 tick 沿当前位置到“当前位置 + 本 tick 速度”的线段检查碰撞，方块先截断线段；目标包围盒固定膨胀 `0.3F`；实体命中调用 `damageEntity(projectile, 0.0F)`。
- [EntityLiving.java](https://github.com/Attano/Spigot-1.8/blob/master/net/minecraft/server/v1_8_R3/EntityLiving.java)：`maxNoDamageTicks=20`；新受击设置 `noDamageTicks=20`、`hurtTicks=10`。剩余免疫大于最大值一半时，伤害不高于 `lastDamage` 的命中被拒绝；所以第二次零伤害杆通常需等待 10 tick。

1.21.11 三核心实际 `ProjectileUtil.computeMargin` 为 `max(0, min(0.3, (tickCount-2)/20))`。出杆初期余量为 0，随后逐渐扩大，到第 8 tick 才达 0.3。高速杆在近距离碰到横移目标时常处于较小余量阶段。1.2.9 完全沿用这个现代判定，未模拟旧版固定余量。现代原生本身已有线段检测，不能将问题简单归结为“飞得快就穿模”。

旧插件另外主动把零伤害杆的 `noDamageTicks` 设为 14，使默认重复杆和接刀在第 4 tick 即可接受。受击动画与伤害免疫不是同一个计时器；4 tick 已能再次 KB 时，上一击动画可能尚未结束。

## 1.2.10 对照与本次修复

2.0 的发布记录对比了当时 1.2.10 与 2.0 Jar 中的 40 个 `combat/rod/compat` 类，逐项 SHA256 一致；该结果保存在 Git 标签 `v2.0` 的 `docs/VERIFICATION.md`。因此可用该标签中的代码核查 1.2.10 的鱼竿逻辑。1.2.10 已使用真实 `THROWN` 零伤害事件、一次独立 KB、即时速度后补受击动画和声音，以及默认 10 tick 共同保护。它命中后移除鱼钩；当前继续保留用户选择的轻微回弹表现。

本次复现的是有条件触发的接受判定缺陷：`KnockbackProfileEvent` 或 `KnockbackModifyEvent` 取消、API 选择不存在的 profile、选中 `enabled: false` 的 profile 时，接口约定是保留原生 KB。旧实现只把完成自定义向量修改的杆记为成功，因此核心已经改变玩家速度，插件却撤回这次受击保护，并跳过即时速度发送及受击反馈。后续快速出杆便可能再次进入命中流程。

2.0.5-r2 分别记录原生 KB 事件接受结果和自定义修改结果。原生事件最终未取消时，即使本次未采用自定义向量，也保留实际向量、共同保护和一次即时速度通知，随后播放一次红闪与受击声音。同一次杆处理中的嵌套 KB 不再形成第二个组件。Folia 清理先检查区域所有权，发送回调产生较新受击时也不会清掉新受击的速度标记。

零伤害受击不扣血，反馈与击退在同一 tick 内完成，不等待红闪结束、不定身、不延后重放 KB。客户端可能在同一帧显示红闪和位移；当前修复不等于已验证真人画面。保护插件真正取消碰撞、伤害或原生 KB 时不强制补打；取消最终速度事件时不补反馈。API 取消自定义修改并不等于取消这些原生事件。

## 碰撞处理

classic 在鱼钩自己的实体调度中，从当前实际位置沿本 tick 的速度做一次固定 0.3 余量的检查，使用核心原有的方块截断、最近目标选择和 `canHitEntityPublic`，不预测或回溯玩家位置、不改变钩子的年龄、不扩展近战距离。

首个可用的调度 tick 即执行，随后每 tick 检查，包括无限距离/寿命、速度倍率为 1 的配置。仅处理飞行中且未挂钩、未落地、未入水的 classic 鱼钩。钓鱼、物品命中和 modern 继续使用原生流程。

找到生物后派发正常 `ProjectileHitEvent`，由现有伤害/KB流程接管。保护插件取消碰撞或零伤害事件均可拦截。2.0.5-r1 恢复 2.0.3/2.0.4 的表现：保留接触后的鱼钩与钓线，让鱼钩轻微向后、向下回弹；撤回 2.0.5 的原生附着及本人隐藏。鱼钩标记为已使用，同一枚钩不会再次尝试伤害或KB。即使保护期已结束或重建监听器，标记仍有效。Folia 要求鱼钩、出杆者和目标均由当前区域拥有，跨区域不排队补打。原生查询仍受核心的已加载区域和可见性规则约束。

先捕获鱼钩入射方向，再完成伤害、KB与立即速度发送，受击反馈沿用 2.0.5 的顺序在速度之后播放。接触后的鱼钩速度为 `(-vx * 0.1, -max(0.05, abs(vy) * 0.1), -vz * 0.1)`，只影响鱼钩，不改写玩家 KB。取消、免疫或未成功发送速度的接触仍标记为已使用并轻微回弹，不强制补 KB。右键收杆在原生拉回之前取消并移除鱼钩，收杆间隔从实际收杆开始计算；距离/寿命限制及切模式清理继续生效。切换到其他物品时核心仍可正常结束钓鱼。详见 [视角、鱼钩与同步](CLASSIC-FEEL.md)。

0.3 是 1.8 鱼竿自身的固定碰撞余量，没有新增调参项。已移除的近战 0.1 膨胀/挥空补刀不受此变更影响。

## 受击保护配置

推荐 `plugins/ModernKnockBack/classic/combat.yml`：

```yaml
hit-interval-ticks: 10
rod-hit-interval-ticks: 10
rod-melee-interval-ticks: 10
```

实际连续杆间隔 = `max(hit-interval-ticks, rod-hit-interval-ticks)`。

实际竿接刀间隔 = 上述两项与 `rod-melee-interval-ticks` 的最大值。

三项接受 1..40 的整数。旧配置中的 4、6 或接刀 1/2 保留在文件中，但不再缩短共同受击窗口。例如旧 `10/4/4` 现在实际执行 `10/10`。`/mkb status` 显示实际间隔和 `rod margin=0.3`。新增字段自动补全、修改前备份；现有 KB 向量与出杆参数保留。

| 默认时序 | 行为 |
| --- | --- |
| T 成功杆命中 | 一次真实零伤害受击、一次 KB、立即发送速度，再播放固定方向红闪及受击声音；同 tick 完成，保留的鱼钩轻微回弹 |
| T～T+9 连续杆或接刀 | 拒绝额外受击与 KB，不排队，不重置保护期 |
| T+10 新杆或新刀命中 | 可接受新的有效攻击；20 TPS 下约 500ms |
| API 取消自定义修改、API 选到无效或禁用 profile | 保留这次原生 KB、即时速度与受击反馈，并保留完整共同保护 |
| 碰撞、伤害、原生 KB 或最终速度事件取消 | 不强制补 KB/受击效果，撤回自身临时状态 |
| 外部延长保护/已有正伤害免疫 | 保留，不逐击清空 |

零伤害杆建立完整的普通免疫，默认 `noDamageTicks=20`，第 10 tick 降到 10。另有按受击者记录的保护，换新鱼钩、换持竿者或外部清零原生计时不能绕过它。处理伤害事件之前就锁住正在进行的同目标杆命中，避免监听器嵌套调用在 MONITOR 之前制造第二击；结束后释放临时锁。

严格禁止窗口内竿接刀叠击是本插件按用户需求提供的规则：原版 1.8 的更高伤害可进入差额伤害分支，因此此处并非逐项复制全部原版伤害语义。“硬直”在此指受击/击退保护，玩家仍可移动、转向、跳跃；不施加定身或延迟后补发 KB。

## 既有修复与复测

继续保留：解除原生挂钩、防拉回、立即速度通知、classic 向量保护、玩家 UUID 排除互推、无挥空补刀。客户端队伍副本不修改真实计分板。保留的鱼钩不在后续接触中再次对生物触发受击；钓鱼和物品处理仍走原生流程。

替换为 `ModernKnockBack-2.0.5-r3.jar` 后正常重启，无需删除配置。用 `/kbtest classic` 与 `/mkb status` 确认模式、版本、实际间隔及`Classic rod`计数。建议在目标服务器检验：

1. 近距离向左右横移玩家连续出杆，比较正中、擦边与明显偏离；隔墙不能命中。
2. 快速连杆并立即切刀，在实际有效窗口内不产生第二次KB；默认10 tick，已有9/9/9配置为9 tick。持续出杆不延长首次保护窗口。
3. 接触后保留鱼钩与鱼线并轻微回弹，右键可收回且不拉回目标；双方及旁观者核对红闪、受击声和立即 KB，生命值不减少。
4. 保留原自定义配置重启，检查向量、出杆速度、模式与实际保护间隔。
5. 与真实 KnockbackSync、反作弊共同联机测试，切 modern 检查恢复原生规则。
6. 对照 API 取消自定义修改与真正取消原生 KB：前者保留原生向量及共同保护，后者不强制受击；保护区和免疫期也不补打。

自动测试和三核心探针覆盖范围见 [验证记录](VERIFICATION.md)。尚未连接真实客户端，延迟、插值和完整对战手感仍须实服验证。
